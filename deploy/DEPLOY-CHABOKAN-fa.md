# راهنمای استقرار روی چابکان (Chabokan) — لندینگ + اپ رسا

معماری انتخاب‌شده: **یک سرویس، یک قبض، دو دامنه.** همان سرویس Next هم اپ PWA را
سرو می‌کند و هم لندینگ استاتیک را — با مسیریابی مبتنی بر دامنه (`src/middleware.ts`).
برای راهنمای عمومی (VPS شخصی یا Liara) به [`DEPLOY-fa.md`](DEPLOY-fa.md) مراجعه کنید.

## معماری

```
                         ┌─ https://<دامنه>.ir (+www)   ← لندینگ (public/landing)
دامنه ──► DNS چابکان ──► │
                         └─ https://app.<دامنه>.ir      ← اپ PWA (Next.js)
                                  همان «هاست Next» چابکان
```

**چطور کار می‌کند؟** متغیر محیطی `LANDING_HOST` روی سرویس تنظیم می‌شود؛ middleware
درخواست‌های دامنهٔ ریشه را به صفحهٔ لندینگ (`public/landing/index.html`) و فایل‌هایش
بازنویسی می‌کند و بقیهٔ مسیرها به اپ می‌روند. وقتی `LANDING_HOST` تنظیم نباشد
(توسعه/تست) همه‌چیز مثل قبل فقط اپ است.

## پیش‌نیازها

- [ ] حساب در [hub.chabokan.net](https://hub.chabokan.net/fa) (اعتبار اولیهٔ رایگان دارد)
- [ ] خرید دامنه — پیشنهاد: پسوند `.ir` برای مخاطب ایرانی
- [ ] ریپوی اپ روی گیت‌هاب: `github.com/AmirheydaripourOdin1133/rasa` (شاخهٔ main)
- [ ] در `public/landing/index.html` عبارت `YOUR-DOMAIN` با دامنهٔ واقعی جایگزین شده باشد (۳ مورد — جست‌وجو کنید: `YOUR-DOMAIN`)

## سرویس «هاست Next» (اپ + لندینگ با هم)

### ساخت سرویس

1. هاب چابکان ← **ساخت سرویس جدید** ← **هاست Next**
2. دیتاسنتر: **ایران** (تأخیر کم برای کاربران + اقامت دادهٔ سلامت داخل کشور)
3. از بخش تنظیمات: نسخهٔ Node = **22 (LTS)**

### منابع (پلن)

اسکریپت `build` پروژه (`next build --turbopack`) حافظهٔ قابل‌توجهی می‌خواهد:

| مسیر | پلن | توضیح |
|---|---|---|
| **الف) بیلد روی سرور** | حداقل **برنز (۱ گیگ RAM)** | ساده‌ترین؛ پلتفرم خودش `npm run build` و سپس `npm start` را اجرا می‌کند |
| **ب) بیلد لوکال، آپلود خروجی** | اقتصادی/پایه کافی است | لوکال `npm run build` بگیرید و خروجی را (با `node_modules` production و `public`) آپلود کنید |

برای شروع مسیر «الف» را پیشنهاد می‌کنیم؛ پرداخت ساعتی است و منابع هر لحظه قابل تغییر است.

### متغیرهای محیطی

در داشبورد سرویس ← بخش متغیرهای محیطی:

```
LANDING_HOST=<دامنه>.ir,www.<دامنه>.ir
```

بدون این متغیر، سرویس فقط اپ است (رفتار امن پیش‌فرض).

### دیپلوی از گیت

در کنسول وب ترمینال سرویس:

```bash
rm -rf $(ls -A) 2>/dev/null
git clone https://github.com/AmirheydaripourOdin1133/rasa.git .
npm install
```

سپس از داشبورد **ری‌استارت** بزنید. پلتفرم طبق `package.json` اجرا می‌کند:

- `build` → `next build --turbopack`
- `start` → `next start` (پورت ۳۰۰۰ — پیش‌فرض چابکان)

### دامنه‌ها و SSL

1. داشبورد سرویس ← بخش **دامنه‌ها** ← **هر دو دامنه** را اضافه کنید:
   - `<دامنه>.ir` و `www.<دامنه>.ir` (لندینگ)
   - `app.<دامنه>.ir` (اپ)
2. رکوردهای DNS که پنل برای هر دامنه پیشنهاد می‌دهد را در DNS ثبت کنید
3. SSL رایگان چابکان برای هر دامنه خودکار صادر و تمدید می‌شود — **HTTPS برای نصب PWA اجباری است**

## چک‌لیست نهایی پس از انتشار

- [ ] `https://<دامنه>.ir` → لندینگ؛ `https://app.<دامنه>.ir` → اپ (onboarding)
- [ ] `https://app.<دامنه>.ir/manifest.webmanifest` → JSON مانیفست
- [ ] لندینگ: دکمهٔ «ورود و نصب مستقیم اپلیکیشن» به `https://app.<دامنه>.ir/` برود (بدون YOUR-DOMAIN باقی‌مانده)
- [ ] نصب PWA روی یک اندروید واقعی (بنر «نصب») + یک آیفون واقعی («افزودن به صفحه اصلی»)
- [ ] حالت آفلاین: بعد از نصب، اپ بدون اینترنت هم پوسته را باز می‌کند (سرویس‌ورکر `rasa-shell-v3`)
- [ ] تقویم شمسی در هر ۳ ورودی تاریخ تنظیم اولیه درست کار کند
- [ ] دکمهٔ «اورژانس ۱۱۵» در اپ کار می‌کند (`tel:` link)

## به‌روزرسانی

لندینگ و اپ در **یک ریپو** هستند (`public/landing/`):

```bash
# لوکال: تست کامل (typecheck + lint + test + build) → کامیت → پوش به گیت‌هاب
# روی چابکان (کنسول سرویس):
git pull
npm install
# سپس ری‌استارت سرویس از داشبورد
```

اگر کش قدیمی دیدید، نام کش سرویس‌ورکر در `public/sw.js` (`rasa-shell-v3`) را bump کنید.

## جایگزین: دو سرویس مجزا (اگر بعداً خواستید جداش کنید)

هر زمان بخواهید، لندینگ را می‌توانید به یک هاست استاتیک ارزان (یا Cloudflare Pages)
منتقل کنید: فقط دامنهٔ ریشه را از این سرویس جدا کنید، محتوای `public/landing/` را روی
هاست استاتیک آپلود کنید و `LANDING_HOST` را از سرویس اپ حذف کنید. اپ بدون تغییر کار می‌کند.

## نکات امنیتی و حریم خصوصی

- دادهٔ درمانی کاربران فقط روی دستگاه خودشان می‌ماند (localStorage) — سرور هیچ دادهٔ بالینی ذخیره نمی‌کند
- middleware فقط صفحهٔ لندینگ را مسیریابی می‌کند؛ هیچ منطق درمانی/داده‌ای در آن نیست (تست‌شده: `tests/unit/landing-routing.test.ts`)
- هیچ secret در ریپو نیست؛ بک‌اند Supabase عمداً وصل نیست
- در صورت اتصال بک‌اند در آینده: کلیدها فقط در «متغیرهای محیطی» داشبورد چابکان، هرگز در گیت

## هزینهٔ تقریبی

فقط **یک سرویس**: هاست Next — با بیلد روی سرور پلن برنز (۱ گیگ)، با بیلد لوکال پلن
اقتصادی/پایه کافی است. SSL برای هر سه دامنه رایگان. تعرفهٔ دقیق را هاب چابکان نشان
می‌دهد؛ با اعتبار اولیهٔ رایگان می‌توانید کل جریان را پیش از پرداخت تست کنید.
